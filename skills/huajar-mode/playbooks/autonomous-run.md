### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.**

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero). If the user will step away, list the external commands the run needs before they go: pushes, PR and tracker writes, merges, worktree commands, and plugin commands. Hand the user one ready-to-paste `permissions.allow` block with a narrow rule for each, such as `Bash(git push *)`, `Bash(gh pr merge *)`, `Bash(git worktree *)`, `Bash(claude plugin *)`, or `mcp__<server>__<tool>` for a tracker write through MCP, and name the settings file it goes in. Write each rule for the shell tool the run uses, `Bash(...)` or `PowerShell(...)`, because one does not cover the other. Write each rule in the form the run calls the command, because `Bash(git push *)` does not match `git -C <path> push`. Do not write the rules yourself with `update-config`, because in auto mode the classifier blocks the agent's own settings edit as self-modification. The classifier also judges each command on its own. A chat approval clears a block only when it names the action and its specifics, and it covers that one action. Writes to protected paths such as `.claude` go to the classifier even when an allow rule matches, so have the user make any settings edit the run needs before they leave. Do not rely on a prefix deny-glob to fence the run, because a reworded command gets around it.
2. Pick the wake mechanism using Cursor's `/loop` command (a built-in, not a huajar-stack skill). An event to watch (CI, a merge, a ref advancing) gets a watcher subagent that wakes you on the event, with a long time-based heartbeat as fallback. No event gets a fixed-interval heartbeat sized to when the result is worth re-checking. Pick each subagent's reasoning level for the job, per the Subagents section.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride.
   Sequence the work via the **sequence-verifiable-units** principle skill, verifying each unit before the next instead of batching checks at the end.
4. Mid-run discoveries that support the goal are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself via huajar-mode. Put out-of-band fixes in their own PR. Do not park reversible work for the human or use `AskQuestion`. Surface only irreversible actions, genuine product or preference calls no experiment can settle, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix.
5. Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved.
6. Stop when the predicate is met. A plateau is not a stop, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state.
